# 润色规则详解

本文件是 `scripts/polish.py` 的判断依据。**规则式润色**：全部是确定性的文本规则，不调用任何模型，
同样的输入永远得到同样的输出——所以它的行为可预期、可审查、可争论。

## 一、边界：只做四件事

| 做 | 不做 |
|---|---|
| ✅ 去掉词表内的口语冗余 | ❌ 改写句式、调整语序 |
| ✅ 修正断句 | ❌ 扩写、补充内容 |
| ✅ 补全标点 | ❌ 翻译 |
| ✅ 整理段落结构 | ❌ 摘要、提炼要点 |
| | ❌ 合并不同含义的句子 |
| | ❌ 删任何实词（只删词表内的口水词） |
| | ❌ 改同音错字（那是 ASR 的问题，见第五节） |

## 二、去口语冗余

### A 类：语气词（独立出现时删）

`嗯` `呃` `啊` `哦` `唉` `诶` `欸` `噢` `喔` `唔`

**删除条件**：前面是标点/句首，或后面是标点/空白——也就是它作为独立的语气词出现时。
如果它夹在两个实词中间（如"这个啊 thing"），**保留**，因为可能是实义用法。

### B 类：话语标记（成对出现时删）

`就是说` `然后呢` `怎么说呢` `对不对` `对吧` `你知道吧` `你知道吗` `其实呢`
`基本上说` `怎么说` `那么呢` `然后就是`

这类词单独出现时可能承载语义，只在**成串出现**（如"就是说…就是说"）时删除。

### C 类：英文口水词

`um` `uh` `you know` `i mean`（大小写不敏感）

### 删除后清理

连续标点合并（`，，` → `，`）、多余空白压成一个。

> 每个删掉的词都会记进 `polish_report.json` 与 `transcript_diff.md`，
> 交付前扫一眼对照表就知道动了什么。

## 三、修正断句

ASR 切出来的片段是**停顿边界**，不是句子边界。中文口播里，一个片段常常停在半句上
（"过去被NPD伤害过的我们" + "不知道如何去描述这类人"），直接按片段断句会得到一地碎片。

### 合并规则

按顺序判断，满足任一条才断句：

| 规则 | 含义 | 目的 |
|---|---|---|
| `MIN_SENT_CHARS = 18` | 累计够 18 字才断 | 避免碎句 |
| `LONG_FRAGMENT = 34` | 单片段超过 34 字自成一句 | 避免长句被硬拼 |
| `LONG_PAUSE = 0.45s` | 下一个片段前有 ≥0.45 秒真实静音 | 说话人真的换气了 |
| `INCOMPLETE_END` | 当前片段以未完成词尾结尾时**不断** | 见下 |

### 未完成词尾（`INCOMPLETE_END`）

`的 地 得 了 着 和 与 或 而 但 却 就 都 也 还 很 更 把 被 给 对 从 向 为 以 让 使 等 个 些 们 是 有 会 要 能 可 那 这 其 之`

以这些字结尾，说明这句话**还没说完**，必须并入下一段。

> 这一条是中文流水账转写里最关键的一条。实测同一条视频：
> 没有这条规则时输出是「过去被NPD伤害过的我们。不知道如何去描述这类人。」
> 加上之后是「过去被NPD伤害过的我们，不知道如何去描述这类人。」

### 片段内部用逗号连接

合并后的片段之间用「，」连接（不是句号）——因为它们是同一口气里的话。

### 长句再切

单个片段超过 40 字时，按连接词（`但是 不过 而且 所以 因为 然后 其实 结果 于是 另外 接下来 首先 其次 最后`）
在语义连接处再切一刀。

## 四、补全标点

### 句末标点

| 条件 | 标点 |
|---|---|
| 句末语气词 `吗 呢 么` | `？` |
| 句末语气词 `啊 呀 哇 哎` | `！` |
| 其他 | `。` |

已有标点的句子不动。

### 枚举补顿号

在**明确枚举语境**下，把并列短项之间补上「、」：
引导词 `比如 例如 包括 有以下 分别是 有这几`，后面跟 3–8 个、每项不超过 8 字的短项时才处理。
其余情况**不动**——宁可少补，不要补错。

## 五、整理段落

段落边界有两个来源：

1. **真实长停顿**：句子开头前有 ≥0.45 秒静音 → 立刻断段（说话人换气 = 换话题）
2. **字数上限**：累计到 `TARGET_PARA_CHARS = 260` 字断一段（硬上限 400）

段落之间空一行；段内的句子连排。

## 六、局限（必须知道）

1. **规则式断句不是语义理解**。它依据停顿与片段边界，
   遇到"语义上该断但语流连贯"或"语流停顿但语义未完"的地方，可能切得不理想。
   这是设计取舍：要可预期、可审查、可离线，就不能依赖模型。
2. **同音错字不会自动改**。ASR 把"声讨"听成"深讨"、"容忍"听成"送容"、"自恋"听成"自念"，
   这些属于**识别错误**，规则式改字有改错的风险。处理方式：
   - 用 `--prompt` 给出题材，从源头减少（实测「NPD/原生家庭」必须给提示）
   - 交付前人工对照 `transcript_diff.md` 订正
   - 更大的模型（`medium`）也能减少这类错误
3. **口语词表是有限的**。没进表的口头语（如"怎么说来着""你懂的"）不会被删。
   需要扩展时改 `scripts/polish.py` 顶部的 `FILLERS_*` 常量。
4. **不处理非语音**。视频里的字幕条、贴纸文字、背景音乐歌词都不在转写范围内。

## 七、参数速查

```bash
python3 scripts/polish.py <输入> [选项]

--out-dir DIR      输出目录（默认当前目录）
--title "标题"     写进润色稿头部
--keep-fillers     保留所有口语冗余（只做断句/标点/分段）
--diff-only        只输出对照表，不写润色稿
```

输入可以是 `transcript_raw.txt`，也可以直接给 `transcript_segments.json`；
若 txt 同目录下存在 `transcript_segments.json`，**会自动优先使用**（有分段信息，断句更准）。

## 八、复核方式

`transcript_diff.md` 给出三部分：

1. **原始逐字稿**（按 ASR 分段）
2. **润色稿**（按自然段）
3. **删掉的口语冗余词清单**（含每个词删了几次）

交付前扫一眼第 3 部分，就能确认"只删了口水词，没动实词"。
